## What each source of variation actually is (investigated, not assumed)

* **Scout `visual_change`**: computed against the previous candidate *in that condition's own
  pool*, so the same frame gets a different value when pools differ. 116 of the 211 scout
  mismatches differ only here; same-time differences have median 0.135, up to 1.0. **A real
  validity defect.**
* **Scout similarity at the same timestamp**: differences are tiny (median 5.6e-6, max 2.6e-4).
  Decoding was checked directly and is deterministic (identical pts and pixel hash whether a time
  is decoded alone or in a batch). The noise comes from GPU batch composition when each
  condition's candidates are scored as a separate batch. Negligible in size, but it breaks exact
  pair identity.
* **Requested-time and source mismatches**: candidates were generated from each condition's own
  retrieval, and pairing accepted times within 0.5 s. **A real validity defect** for the
  controlled comparison.
* **Word-count mismatches**: the control picker took the closest word count with no tolerance.
  **A real defect.**
* **Control could include relevant spans beyond the 3-target cap**: a real code defect, but
  measured to affect **0** saved questions (none had more than 3 relevant segments).
* **Identical inputs, different gains**: the 26-feature vector cannot distinguish these states.
  This is representation ambiguity, not proof that a richer model would separate them.

## Statements in earlier reports that were too strong

| Earlier statement | Correction |
|---|---|
| "LongVideoBench cannot test the hypothesis" / "there is no signal for any controller" | Too strong. The result concerns this subset (T* questions), deletion damage, this candidate set, the 26-feature representation, one scorer and one answerer. |
| "No difference" between paired and unpaired | Not significantly different. A nonsignificant difference is **not** evidence of equivalence. |
| The quoted subtitle span is "answer-relevant speech" | It is a **temporal anchor**, not necessarily speech that contains the answer. Future records keep evidence types separate. |
| Internal test split = held-out benchmark | All 440 questions come from official LongVideoBench **validation**, repartitioned internally. It is development evidence, not an untouched LongVideoBench test, and no standard zero-shot LongVideoBench score may be reported from it. |
| Premise check interval | Bootstrapped by question; the 208 questions come from 108 videos, so it must cluster by video. A nonpositive mean over mostly irrelevant candidates also does not show that no useful evidence exists. |
| +0.14 for question-similar frames | One comparison among many on 43 questions, not corrected for multiple comparisons. Evidence about this experiment's selectors only. |
| Frame-count selectivity as the headline metric | Secondary. The primary endpoint is answer recovery under important-speech failure at equal total cost. |
| Tuned controller is "cheap" | Its logged clean-test latency (≈1,866 ms) exceeds transcript-only (≈1,302 ms), because every candidate is decoded and scouted before the decision. |
